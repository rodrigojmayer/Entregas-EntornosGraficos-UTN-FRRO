    Visualización: Al no tener texto antes de cerrar la etiqueta, no se visualiza nada en la pantalla. Además, contiene un espacio erróneo en la URL (www. google.com.ar) que rompería el enlace.

<a href="#">Click aquí para ir a Google</a> 
    Código: Enlace con ancla vacía (#).
    Visualización: Se muestra como un hipervínculo normal, pero al hacer clic no navega a otra página, sino que desplaza la ventana hacia la parte superior de la página actual.

3.b) 
 
    <p>
        <img src="im1.jpg" alt="imagen1" />
        <a href="http://www.google.com.ar">Click aquí</a>
    </p> 
    Código: La imagen está fuera de la etiqueta <a>. Solo el texto "Click aquí" está envuelto por el hipervínculo.
    Visualización: Muestra la imagen seguida del texto. Solo el texto es cliqueable y dirigen a Google; la imagen es estática.

    <p>
        <a href="http://www.google.com.ar">
            <img src="im1.jpg" alt="imagen1" />
        </a> 
        Click aquí
    </p>
    Código: La etiqueta <a> envuelve exclusivamente a la imagen <img>. El texto "Click aquí" queda fuera.
    Visualización: Muestra la imagen seguida del texto. Solo la imagen es cliqueable; hacer clic en el texto no realiza ninguna acción.

    <p>
        <a href="http://www.google.com.ar">
            <img src="im1.jpg" alt="imagen1" />
            Click aquí
        </a>
    </p> 
    Código: Una única etiqueta <a> envuelve tanto a la imagen <img> como al texto "Click aquí".
    Visualización: Muestra la imagen y el texto juntos. Ambos elementos (imagen y texto) forman un único bloque cliqueable que dirigen al mismo enlace.

    <p>
        <a href="http://www.google.com.ar">
            <img src="im1.jpg" alt="imagen1" />
        </a> 
        <a href="http://www.google.com.ar">
            Click aquí
        </a>
    </p> 
    Código: Dos etiquetas <a> separadas e independientes, una para la imagen y otra para el texto, pero apuntando a la misma URL.
    Visualización: Funcionalmente se percibe similar al bloque 3 (tanto imagen como texto son cliqueables hacia Google), pero técnicamente el navegador los trata como dos hipervínculos distintos.


3.c) 
 
 
    <ul>   
        <li>xxx</li> 
        <li>yyy</li> 
        <li>zzz</li> 
    </ul>
    Código: Utiliza la etiqueta <ul> (unordered list).
    Visualización: Genera una lista no ordenada. Cada elemento (<li>) aparece precedido por un viñeta sólida (bullet / punto) por defecto y con margen/sangría a la izquierda.

    <ol> 
        <li>xxx</li> 
        <li>yyy</li> 
        <li>zzz</li> 
    </ol> 
    Código: Utiliza una única etiqueta <ol> (ordered list) envolviendo a los tres elementos.
    Visualización: Genera una lista ordenada continua. El navegador numera automáticamente los elementos de forma secuencial: 1. xxx, 2. yyy, 3. zzz.

    <ol> 
        <li>xxx</li> 
    </ol> 
    <ol> 
        <li value="2">yyy</li> 
    </ol> 
    <ol> 
        <li value="3">zzz</li> 
    </ol> 
    Código: Abre y cierra tres listas ordenadas <ol> independientes, usando el atributo value en los <li> de la segunda y tercera lista para forzar el número inicial.  
    Visualización: Muestra visualmente la numeración 1. xxx, 2. yyy, 3. zzz, pero a diferencia del bloque 2, se crean tres listas separadas. Esto genera un espaciado/margen vertical adicional entre cada elemento debido a los márgenes por defecto que cada etiqueta <ol> agrega en el navegador.

    <blockquote> 
        <p>
            1. xxx<br /> 
            2. yyy<br /> 
            3. zzz
        </p> 
    </blockquote>
    Código: No utiliza etiquetas semánticas de lista (<ul>, <ol>, <li>). En su lugar, usa un bloque de cita (<blockquote>), un párrafo (<p>) y saltos de línea (<br />), escribiendo los números manualmente en el texto.
    Visualización: El texto aparece con una sangría (indentación) de bloque grande a la izquierda propia de <blockquote>. Aunque visualmente se leen los números 1, 2 y 3, carece de semántica de lista, por lo que no es reconocido como una lista accesible por los lectores de pantalla o motores de búsqueda.

3.h)


    <form id="form1" name="form1" action="procesar.php" method="post" target="_blank"> 
        <fieldset> 
            <legend>LOGIN</legend> 
            Usuario: <input type="text" id="usu1" name="usu1" value="xxx" /><br /> 
            Clave: <input type="password" id="clave1" name="clave1" value="xxx" /> 
        </fieldset> 
        <input type="submit" id="boton1" name="boton1" value="Enviar" /> 
    </form>
    Código:
    Método de envío: method="post", los datos viajan ocultos en el cuerpo de la petición HTTP hacia procesar.php.
    Seguridad de campos: Usa type="password" en la clave y precompleta ambos campos con value="xxx".
    Agrupación semántica: Utiliza <fieldset> y <legend>LOGIN</legend> para enmarcar el formulario.
    Botón: Usa type="submit", el cual ejecuta el envío del formulario.
    Visualización y Comportamiento: Muestra un recuadro con el título "LOGIN" incrustado en el borde superior. Los campos ya vienen rellenos con "xxx" (la contraseña oculta con puntos/asteriscos). Al hacer clic en "Enviar", abre una nueva pestaña (target="_blank") enviando los datos por POST.

    <form id="form2" name="form2" action="" method="get" target="_blank"> 
        LOGIN<br /> 
        <label>Usuario: <input type="text" id="usu2" name="usu2" /></label><br /> 
        <label>Clave: <input type="text" id="clave2" name="clave2" /></label><br /> 
        <input type="submit" id="boton2" name="boton2" value="Enviar" /> 
    </form>
    Código:
    Método de envío: method="get", los datos se adjuntan en la URL de destino (?usu2=...&clave2=...).
    Destino: action="" (recalcula o recarga la misma página actual).
    Seguridad de campos: Usa type="text" para la clave en lugar de password.
    Accesibilidad y estructura: Asocia las etiquetas usando la etiqueta <label> envolviendo el texto y el <input>. No usa <fieldset>.
    Visualización y Comportamiento: El título "LOGIN" aparece como texto plano sobre los campos, sin recuadro. La contraseña no se oculta mientras se escribe. Al hacer clic en "Enviar", abre una nueva pestaña recargando la misma URL exponiendo los datos en la barra de direcciones.

    <form id="form3" name="form3" action="mailto:xx@xx.com” enctype=text/plain method="post" target="_blank"> 
        <fieldset> 
            <legend>LOGIN</legend> 
            Usuario: <input type="text" id="usu3" name="usu3" /><br /> 
            Clave: <input type="password" id="clave3" name="clave3" /> 
        </fieldset> 
        <input type="reset" id="boton3" name="boton3" value= "Enviar" /> 
    </form>
    Código:
    Envío por correo: action="mailto:xx@xx.com" con enctype="text/plain".
    Error en botón: Utiliza type="reset" en lugar de type="submit", aunque su texto sea value="Enviar".
    Error de sintaxis: Falta la comilla de cierre en action="mailto:xx@xx.com” y faltan comillas en enctype=text/plain.
    Visualización y Comportamiento: Estéticamente se ve similar al formulario 1 (con recuadro <fieldset>), pero no envía los datos. Al hacer clic en "Enviar", el botón con type="reset" borra el contenido que el usuario haya escrito en los campos. Además, el intento de envío por correo mediante mailto: depende de que el cliente tenga configurado un programa de correo local (como Outlook o Mail).

    <p>
        <label>
            <input type="radio" name="opcion" id="X" value="X" />
            X
        </label>
        <br /> 
        <label>
            <input type="radio" name="opcion" id="Y" value="Y" />

            <option>Mayo</option>

        </optgroup> 
        <optgroup label="Caso 2"> 
            <option>Mayo</option>

        </optgroup>

    Código: Usa un elemento <select> básico con el atributo name="lista". Agrupa las opciones visualmente mediante etiquetas <optgroup> con sus respectivos títulos (label).
    Visualización y Comportamiento: Muestra una lista desplegable clásica (combo box) de una sola línea. Al hacer clic se despliega mostrando las categorías "Caso 1" y "Caso 2" en negrita e inhabilitadas para selección, con sus opciones indentadas. Solo se puede seleccionar una única opción. En el envío del formulario se transmite un único valor bajo la clave lista.

    <select name="lista[]" multiple="multiple"> 
        <optgroup label=" Caso 1"> 
            <option>Mayo</option> 
            <option>Junio</option> 
        </optgroup> 
        <optgroup label=" Caso 2"> 
            <option>Mayo</option> 
            <option>Junio</option> 
        </optgroup> 
    </select>
    Código: Agrega el atributo multiple="multiple". Modifica el nombre a name="lista[]" utilizando la sintaxis de corchetes para indicar al servidor (como PHP) que recibirá un arreglo (array) con los múltiples valores seleccionados.
    Visualización y Comportamiento: Se renderiza como un cuadro de lista abierto de varios renglones visibles (en lugar de un desplegable). Permite seleccionar múltiples opciones simultáneamente manteniendo presionada la tecla Ctrl (o Cmd en macOS) o Shift.
